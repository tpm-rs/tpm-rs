# tpm-rs Architecture & Guidelines

## High-Level Architecture
The `tpm-rs` project is a Rust implementation of a TPM 2.0 stack. It is divided into multiple crates to separate concerns such as wire format marshalling, core TPM types, execution engine logic, cryptographic backends, platform-specific bindings, client libraries, and simulator components.

### Crate Responsibilities
- **`tpm2`**: Core types, structures, constants, errors, command/response definitions, and wire format marshalling/unmarshalling traits (`Marshal` and `Unmarshal`) for communicating with a TPM 2.0 device. Commands follow the upstream design: `Command: Message` and `UnmarshalMessage`. Each command struct holds its command handles (plain `Handle` fields, first) and each response struct (`tpm2::commands::responses`) holds its response handles. `Marshal` covers only the parameter area, and the handle area is `Message::handles()`. The cryptography interfaces live in `tpm2::crypto`: upstream's `Hash`/`Hmac`/`Cmac`/`Symmetric` (one-shot, with `SymmetricKey`/`ModeIv`/`Direction`), `Rng`/`Random`, `kdfa`/`kdfe` and `ConstantTimeEq`, with `CryptoError { Unsupported, Internal }` and `CryptoProvider::KNOWN_ANSWER_TESTS` (default `true`; only test doubles with fake algorithms set it to `false`, so that the TPM's algorithm self tests do not fail on them). Semantic failures (bad signature, invalid point, bad padding, and so on) are returned as `Ok(false)`/`Ok(None)`. They are extended with `Asymmetric`/`AsymmetricSign`/`Ecc`, `kdfa_bits`/`kdfe_bits` and the `CryptoProvider` super-trait. Symmetric algorithm types are `AlgSym`, `TpmtSymDefObject { alg, mode }`, `TpmiAlgCipherMode` and `TpmiAlgSymMode { Cmac, Cipher(..) }`. Also defines the `Connection` transport trait (raw `transact`, plus typed `execute<'a, Cmd: Command>(cmd, rsp: &'a mut [u8]) -> Result<Cmd::Response<'a>, errors::ExecuteError>`, which defaults to `platform::execute::run_command`), the per-command handle metadata `commands::{command_handles_count, handle_requires_auth}` (used by both `tpm2-impl` and `run_command`), and the platform interfaces (`tpm2::platform`: `execute` (`run_command`, generic over any `Connection`: builds the wire command with one empty `TPM_RS_PW` session per handle that requires authorization, transacts, and parses the response; plus the `CmdHeader`/`RespHeader` wire headers), `TpmPlatform`, which borrows its crypto/storage/timer/RNG components and optionally (`TpmPlatform::firmware`, `with_firmware`; `None` from `TpmPlatform::new` = no firmware-limited/SVN-limited hierarchies, `TPM_RC_FW_LIMITED`/`TPM_RC_SVN_LIMITED`) a shared `&(dyn firmware::TpmFirmware + Sync)` (Firmware Secret, Firmware SVN Secrets, current/maximum SVN; `SimulatedFirmware` is the reference platform's insecure dummy with atomics, hash 0, SVN 10, max 255), `NvStorage`, `TpmTimer`, and `PcrState`). The algorithms, ECC curves and key sizes of the TPM are the Cargo features of `tpm2` (there is no runtime profile): its default features are exactly what `tpm2-impl` implements (`TPM_CAP_ALGS`/`TPM_CAP_ECC_CURVES`: SHA-1/256/384/512, AES-128/256, CTR/OFB/CBC/CFB/ECB, NIST P-224/256/384/521 and BN P-256, RSA-1024/2048, RSASSA/RSAPSS/RSAES/OAEP, ECDSA/ECDH/ECDAA; the workspace dependency of `tpm2` lists them, except `sha512`). The `TPMI_ALG_*`/`TPMI_ECC_CURVE`/`TPMI_RSA_KEY_BITS` conversions and scheme selectors reject values of disabled features with their usual errors, and the profile-dependent capacities follow from the enabled features (`TPM2B_PUBLIC_KEY_RSA` 256, `TPM2B_PRIVATE_KEY_RSA` 640, `TPM2B_ENCRYPTED_SECRET` 256, `TPM2B_PRIVATE` 910, `TPM2B_TEMPLATE` = unpadded `sizeof(TPMT_PUBLIC)` 350 (`limits::Template`), `TPM2B_ECC_PARAMETER` 66, `HASH_COUNT` 4). Features beyond the defaults: the other algorithms (`sm3_256`, `sha3_*`, `aes192`, `sm4_128`, `camellia*`, `cmac`, `rsa3072`/`rsa4096`, the other curves, `sm2`, `ecschnorr`, `ecmqv`), `eddsa`, `hkdf`, `mlkem` and `mldsa` (their types exist but are accepted and sized only with the feature), and profile settings that differ between TPM implementations (`max-cap-buffer-3072`, `max-nv-index-size-8500`, `tpma-object-fixed-firmware`). SHA-512 is optional: every crate that uses `tpm2` has a default `sha512` feature forwarding to `tpm2/sha512` and to the `sha512` of its workspace dependencies (which the workspace declares without default features), so a build of a root crate with `--no-default-features` (plus its other features) is a TPM without SHA-512, like a C reference built without `ALG_SHA512`: `tpm2-impl` then drops it from `TPM_CAP_ALGS`, the PCR banks and the event digests (`handler::capability::is_enabled_by_features`), uses SHA-384 as `context_integrity_hash_alg()` (tickets, context blobs, `TPM_PT_MAX_DIGEST`), and the `TPM2B_DIGEST`-dependent capacities shrink (`TPM2B_PRIVATE` 846, `TPM2B_TEMPLATE` 334). Cargo unifies features, so enabling more `tpm2` features anywhere in a build widens the TPM built with it; tests of algorithms outside the defaults are `#[cfg(feature = ...)]`-gated, and E2E tests send unimplemented values as patched raw bytes (`_common::put_u16`, `grow_command`, `execute_with_corrupted_bytes_status`). `platform::pcr::DEFAULT_PCR_BANKS` (SHA-256, SHA-384) are the banks `PcrState::default` allocates.
- **`tpm2-impl`**: The core execution engine (`TpmEngine`) and command handlers implementing TPM 2.0 commands, session authentication, encryption, and state management. `TpmEngine` owns both its `TpmPlatform` (`engine.platform`) and the mutable TPM state (`engine.state: GlobalState`), and implements `tpm2::Connection` (each `transact` executes the command in-process). The `platform_connection` module defines `SimulatorPlatformSignal` (the MSSIM platform-port signal codes) and, behind the opt-in `std` feature (which adds `anyhow`; the engine stays `no_std` without it), the `PlatformConnection` trait (not a `Connection` subtrait) (`signal_platform(command, stream: Option<&mut S>) -> anyhow::Result<bool>` for the MSSIM platform port and `transact_platform(command: u32, stream: &mut S) -> anyhow::Result<bool>` for raw MSSIM command-port transactions such as `TPM_SEND_COMMAND` with a locality or `_TPM_Hash_*`; `true` = session end; pass `NO_STREAM` for no stream). Handlers read commands with `try_unmarshal_handles::<Cmd>()` and `try_unmarshal_command::<Cmd>(handles)`, validate handle interface types (`TPMI_DH_*`, `TPMI_SH_*`, `TPMI_RH_*`) with `handle_checks::{check, Tpmi}`, resolve hierarchies with the `hierarchy` module (firmware-limited/SVN-limited hierarchies: `decompose`/`normalize` to the base hierarchy for authorization, enables and flushes; `TpmEngine::validate_hierarchy` for the load status; `hierarchy_proof`/`hierarchy_primary_seed` derive their proofs and seeds with Part 1's KDFa from the platform's firmware secrets; objects keep the limited handle as `TransientObject::hierarchy`, also for their tickets), and write responses with `write_response_message`. The RSA sensitive value of a private area is the CRT form (P, Q, dP, dQ, qInv in the TCG reference's packed layout, `CRT_FORMAT_RSA`) under a fixedTPM parent and the prime everywhere else (`handler::rsa_sensitive`, on `Asymmetric::rsa_private_key_to_crt`). The algorithm self tests (`self_test`: TPM2_SelfTest/IncrementalSelfTest/GetTestResult, `TPM_RC_NEEDS_TEST`, Failure mode) are a port of the references' `AlgorithmTests.c`/`CryptSelfTest.c` (`ENABLE_SELF_TESTS = YES`) with their known-answer vectors: `engine.self_test` (`g_toTest`, reset at `_TPM_Init`) is outside `GlobalState`, every cryptographic operation goes through `TpmEngine::crypto()` (`self_test::Tested`, the provider with the on-demand tests of hashes/HMAC, symmetric ciphers, KDFa (`self_test::kdfa_bits`) and ECC point multiplications), and the RSA/ECDSA/ECC-key operations call `TpmEngine::do_self_test` where the references' `TPM_DO_SELF_TEST()` runs (the RSAES/OAEP/PSS/ECDSA tests draw from the DRBG; differential.md item 49). The crate also provides the in-memory `storage::ram_storage_mock::RamStorageMock` NV storage, and `storage::nv_capacity`, which models the reference's NV space accounting (`NvTestSpace()`; fixed `sizeof(OBJECT)`/`sizeof(NV_INDEX)`, `MIN_EVICT_OBJECTS`/`MIN_COUNTER_INDICES` reserves, orderly RAM) for `TPM_RC_NV_SPACE` in EvictControl/NV_DefineSpace. Profile features of `tpm2-impl` (all off by default, the TCG reference profile; with several values the largest applies): `max-command-size-8192` (`MAX_COMMAND_SIZE`/`MAX_RESPONSE_SIZE`, exported), `max-context-size-2168`/`-2680`/`-4344` (`MAX_CONTEXT_SIZE`, default 2264), `min-evict-objects-7`/`-9` (default 2), `nv-memory-size-32k`/`-128k` (`nv_capacity::NV_MEMORY_SIZE`, default 16384; the storage table `manager::MAX_ITEMS` scales with it), `ecc-parameters-null-kdf` (`ECC_PARAMETERS_REPORT_KDF`), `act-a` (the Authenticated Countdown Timer `TPM_RH_ACT_A` in addition to `TPM_RH_ACT_0`; it also moves `nv_capacity::NV_INDEX_RAM_DATA` from 4644 to 4784) and `ntc2-vendor-commands` (`NTC2_VENDOR_COMMANDS`: `ibmswtpm2`'s Nuvoton `NTC2_PreConfig`/`NTC2_LockPreConfig`/`NTC2_GetConfig`, not in the TCG spec, with a RAM-only configuration `GlobalState::ntc2_config` kept across `_TPM_Init`). Vendor commands (`V` bit): `engine::VENDOR_COMMANDS` (always `TPM2_Vendor_TCG_Test`, plus the NTC2 commands with the feature; handlers in `handler/vendor.rs`) follow the library commands `SUPPORTED_COMMANDS` in `TPM_CAP_COMMANDS`/`TPM_CAP_AUDIT_COMMANDS` (`engine::implemented_commands_in_order`, `command_list_start`), the command counts and the audit bitmap (`command_audit::LIBRARY_COMMAND_SLOTS`). The ACTs live in the `act` module (`IMPLEMENTED_ACTS`, `ActState` in `GlobalState::act`): `TPM2_ACT_SetTimeout` posts a pending value (`TPM_RC_RETRY` while one is pending) that the next once-per-second tick applies and counts down; the ticks are the whole seconds of the platform timer since the last power on (`platform_timer_reset`), applied lazily before each command (`TpmEngine::act_catch_up`) and dropped from `_TPM_Init` until `TPM2_Startup`; `TPM2_Shutdown(TPM_SU_STATE)` saves the timeouts (halved unless written since `TPM2_Startup`), `signaled` and the ACT policies with the other state-save data for TPM Resume; the ACT authValue is platformAuth (only while phEnable) and the ACT policy is set by `TPM2_SetPrimaryPolicy`. White-box tests live in the `tests/` directory (integration-test files such as `tests/engine.rs`, `tests/lifecycle_findings.rs`, sharing `tests/common.rs`) plus in-crate `#[cfg(test)]` modules.
- **`tpm2-crypto`**: Pluggable cryptographic backend implementations of the TPM 2.0 platform crypto interfaces:
  - **`tpm2-crypto/rust`**: Pure-Rust cryptographic implementations.
  - **`tpm2-crypto/crux`**: Formally verified cryptographic backend based on `libcrux`.
  - **`tpm2-crypto/bssl`**: BoringSSL-based cryptographic backend.
  - **`tpm2-crypto/tests`**: Cryptographic test suite verifying provider implementations against test vectors and edge cases.
- **`tpm2-platforms/linux`**: Platform-specific abstractions and environment bindings (storage, clock, crypto integration) for Linux. `create_linux_platform(crypto, storage, timer, platform_rng, firmware)` builds a `TpmPlatform` borrowing the given crypto provider, storage, `LinuxTimer`, `LinuxRng` and firmware identity (`&(dyn TpmFirmware + Sync)`).
- **`tpm2-simulator`**: A simulated TPM environment providing an MSSIM TCP server interface (binary in `src/main.rs`) for development and testing without hardware. The library exposes the in-process `Simulator` (command interface: only `tpm2::Connection`: `transact` over the MSSIM command path at locality 0, and the default `execute(cmd, rsp)`, i.e. `tpm2::platform::execute::run_command` sending through `transact`, where handles travel inside the command and response and the response borrows from the caller's `rsp` buffer; there is no inherent `Simulator::execute`); platform signals and raw command-port transactions: `tpm2_impl::PlatformConnection::{signal_platform, transact_platform}` (the TCP server in `main.rs` uses only these public interfaces), both re-exported with `SimulatorPlatformSignal`/`NO_STREAM` from `tpm2_simulator`) and the `create_simulator!()` macro, which builds a self-contained simulator that is powered on, NV-enabled and started with `TPM2_Startup(TPM_SU_CLEAR)`. The MSSIM `ACT_GET_SIGNALED` platform signal reports the `signaled` attribute of an ACT (`TpmEngine::act_signaled`). `Simulator::new(crypto, storage, timer, platform_rng, firmware: &SimulatedFirmware)`; the `SetFirmwareHash`/`SetFirmwareSvn` platform signals (MSSIM `TPM_SET_FW_HASH`/`TPM_SET_FW_SVN`, a big-endian 32-bit payload) install a firmware image with another hash/SVN (the Firmware Secret / the SVN limit of the SVN-limited hierarchies; `reset_reference` restores the default). The `NvOn`/`NvOff` platform signals toggle NV availability (like `_plat__SetNvAvail`/`_plat__ClearNvAvail`); while NV is off, commands that need NV fail with `TPM_RC_NV_UNAVAILABLE`. `Simulator::reset_reference(pid, realtime_ms)` resets a reference simulator in place (same state as a new `create_reference_simulator!(pid, realtime_ms)`, no leaked components); The NV backing store is a `RamStorageMock<NV_STORAGE_SIZE>` (twice `NV_MEMORY_SIZE`, 32 KiB by default), and its command/response buffers grow with `tpm2_impl::MAX_COMMAND_SIZE`/`MAX_RESPONSE_SIZE`. `TPM_SIMULATOR_LOG_ERRORS` (`LOG_ERRORS_ENV`) enables the per-error `SIMULATOR: CMD .. -> RC ..` log on stderr (off by default).
- **`tpm2-client`**: Client library for communicating with a TPM 2.0 device or simulator.
- **`testing`**: End-to-end integration test crate exercising the full TPM stack. Every test talks to a `testing::tpm::Tpm` (`Tpm::new()`, re-exported from `_common`/`test_utils` together with `SimulatorPlatformSignal`), a `tpm-rs` simulator with the C references' random-number generation and a virtual clock (`create_reference_simulator!(pid, realtime_ms)`) reached only through its command interface: typed `execute`, raw `transact`/`send_command(locality, bytes)`, `signal_platform` (power-on + NV-on + `TPM2_Startup` is the `_common::power_on_start_up` helper, not a simulator method), `set_firmware_hash`/`set_firmware_svn` (the firmware platform signals) and `hash_start`/`hash_data`/`hash_end`. In a differential build (one `target-*` feature), the same `Tpm` mirrors every interaction to the C reference TPM of the target (see **Differential testing**), so the same tests serve as both the `tpm-rs` E2E tests and the differential tests. Tests live in `tests/` as two test targets: `go` (Go parity tests, `tests/go/` with crate root `tests/go/mod.rs`) and `e2e` (topic-focused test files `tests/e2e/<topic>.rs`, no other subfolders, linked from `tests/e2e/mod.rs`). Topic files are one per command or feature area (e.g. `nv_define_space.rs`, `policy_pcr.rs`, `context_save_load_object.rs`, `create_loaded_validation.rs`). Every topic file starts with a `//!` doc describing what it tests and every test fn has a `///` doc; test and file names describe the behavior under test (no generic prefixes/suffixes such as `test_`, `_tests`, `adv`, `findings`, `challenger`, `impl`, `extra`, `custom`, `milestone`). Tests are strictly black-box: they must not inspect/mutate simulator internals (the crate depends on `tpm2-impl` only for its profile features and profile constants such as `MAX_COMMAND_SIZE`, `ECC_PARAMETERS_REPORT_KDF` and `storage::nv_capacity`, which tests use to compute profile-dependent expectations); every TPM interaction goes through the `Tpm` command interface (client-side crypto uses `_common::CLIENT_CRYPTO`). The library (`src/`) holds the shared code: `src/tpm.rs` (`Tpm`, the virtual-time `sleep`), `src/differential/` (in a differential build: `mod.rs`, the reference-process client `Reference` and `Implementation` (`Implementation::TARGET`); `protocol.rs`, the pipe protocol; `server.rs`, the safe comparison server the reference binary runs), and all reusable non-test helpers (command execution with password/HMAC sessions, raw command builders, templates, reference crypto, constants) in `src/_common.rs`, also re-exported as `test_utils` (the path the Go parity tests use; both test crate roots import `testing::{_common, test_utils}` so tests write `crate::_common::…`/`crate::test_utils::…`).
- **Differential testing** (`target-*` features of `testing`): a differential build compares `tpm-rs` with **one** C reference TPM, the target, selected by exactly one feature: `target-mstpm20` (the public TCG (Microsoft) reference implementation `https://github.com/TrustedComputingGroup/TPM` at `3b1f0e623f244abe2015df9e3ba86de5c9118524`, patched by `testing/patches/mstpm20/`), `target-mstpm20-v185` (version 185, the TCG-internal `https://github.com/TrustedComputingGroup/TPM-Internal` on branch `185-feature` at `5b5e8df4142885bbd7a947dd064c3dc1b812a979`, patched by `testing/patches/mstpm20-185-feature/`; only TCG members can clone it) or `target-ibmswtpm2` (the IBM software TPM `https://github.com/kgoldman/ibmswtpm2` at `e1df46e46fc2671e55372d65f27ecbb3c789d992`, patched by `testing/patches/ibmswtpm2/`). Each target enables the internal `differential` feature and the `tpm2`/`tpm2-impl` profile features that give `tpm-rs` that reference's profile (`target-mstpm20`: `tpma-object-fixed-firmware`, `max-context-size-2168`, `act-a`; `target-mstpm20-v185`: `tpma-object-fixed-firmware`, `max-cap-buffer-3072`, `max-nv-index-size-8500`, `max-command-size-8192`, `max-context-size-4344`, `min-evict-objects-9`, `nv-memory-size-128k`, `ecc-parameters-null-kdf`; `target-ibmswtpm2`: `max-context-size-2680`, `min-evict-objects-7`, `nv-memory-size-32k`, `ntc2-vendor-commands`, `act-a`; `build.rs` compiles it with `-DTPM_NUVOTON` like its makefile), so those settings need no `profile-*` patch; prefer such a feature over a new profile patch when a reference's profile value differs (table in `differential.md` M.1). Building without a target is a compile error. `make test-differential` runs the three targets one after the other (`make test-<target>` one). `testing/build.rs` clones the target at its pinned commit, applies every patch of its patch directory in file-name order (one patch file per fix, named `<classification>-<fix>.patch` with the classification `bug-fix` (spec-deviation bug fix), `build-fix`, `harness` (harness plumbing), `platform` or `profile` (setting), each starting with a header that explains and classifies it; no patch changes how a reference draws random numbers), compiles it into a symbol-isolated static library whose only global symbols are its entry points with a per-reference prefix (`difftest_mstpm20_*`/`difftest_ibmswtpm2_*`, renamed by `objcopy --redefine-sym`; `build.rs` checks the library's symbol interface with `nm`) and links it into the `testing` library (`rustc-link-lib`, so it reaches every binary using it, including the fuzz targets; `links = "tpm-references"` also exposes `DEP_TPM_REFERENCES_<NAME>_ARCHIVE`; the version label is the compile-time env `DIFFERENTIAL_<NAME>_VERSION`; the `reference-rng` feature always uses `public` `mstpm20`), hosted by the binary `reference` (`testing/src/bin/reference.rs`). The only harness hooks in the C code are the `difftest_*` entry points (`harness-difftest-entry-points.patch`; `harness-difftest-firmware.patch` adds `difftest_set_firmware_hash`/`difftest_set_firmware_svn`, which the harness also calls with the defaults at every (re)initialization, for `Tpm::set_firmware_hash`/`set_firmware_svn`; `difftest_advance_clock` delivers the ACT ticks `_plat__ACT_Tick()` of the whole virtual seconds since the last power on, as `tpm-rs` counts them) and the virtual clock (`harness-virtual-clock.patch`: `_plat__RealTime()` returns `difftest_virtual_ms()`). All FFI is in `testing/src/differential/inproc.rs`, the only `unsafe` code of `testing` (the crate root uses `#![deny(unsafe_code)]` with `differential`, `#![forbid(unsafe_code)]` without it): the prefixed entry points of the target (`Implementation::TARGET`; only its archive is linked) behind the safe `CReference` (a `server::Backend`; at most one per process, `CReference::acquire`), the callbacks the C code shares (`difftest_getpid`, `difftest_virtual_ms`), a glibc `rand()`/`srand()` port (the reference's `rand`/`srand` are redirected by `objcopy` to `difftest_<name>_rand`/`srand`, on `tpm2_platform_linux::GlibcRand`), `clock_gettime`, and the stdout takeover. The binary `testing/src/bin/reference.rs` only calls `inproc::serve_process(Implementation::TARGET)`, which runs `testing::differential::server::serve`. Every `Tpm` launches one child process of the target (`testing::differential::Reference`; the C references keep their state in globals, so one process per TPM lets tests run in parallel and a test use several TPMs). The `Tpm` first chooses the seed of the references' random number generation (`testing::seed::ReferenceSeed::choose`: the test process's ID and its current monotonic ms, or `TPM_REFERENCE_SEED`), builds its `tpm-rs` simulator from it (`create_reference_simulator!(pid, realtime_ms)`) and passes it to each reference process as `TPM_REFERENCE_SEED` in its environment; the process adopts it (its `getpid()` is redirected at link time to `difftest_getpid` in `inproc.rs` by an `objcopy --redefine-sym` step in `build.rs`, no C patch; its virtual clock starts at the seed's real time), confirms it in a handshake (pid + initial `_plat__RealTime()`), and then talks over stdin/stdout pipes (`differential::protocol`: length-prefixed requests `Exchange`/`AdvanceClock`/`Signal`/`HashStart`/`HashData`/`HashEnd`/`SetFirmware`, one ok/error reply each; each reference process points fd 1 at stderr so C output cannot corrupt the channel). Each command, signal, `_TPM_Hash_*` indication and sleep goes to `tpm-rs` first and then to the reference, which compares its response with the `tpm-rs` response sent along; it must be byte-identical, including every random value (with documented exceptions in `server.rs` and `differential.md`, some specific to one `Implementation`, for implementation-defined blobs, capability tables, and unsupported features; a `TPM2_ContextLoad` of a blob `tpm-rs` saved is translated to the reference's blob in the command bytes); any other difference is an error reply that panics at the diverging command. Every `Tpm` is mirrored to the target only (`testing::differential::References`, `selected() == [Implementation::TARGET]`); since it shares the `Tpm`'s seed, it draws the same random values as `tpm-rs`. Every `Tpm` prints `tpm-rs: TPM_REFERENCE_SEED=<pid>:<realtime_ms>` on stderr; setting `TPM_REFERENCE_SEED` to that value makes every `Tpm` use it and derives client-side randomness (`_common::client_random`, `client_rng`) from the seed and test name, so a failing test can be reproduced. The binary is found via `REFERENCE_BIN` or next to the test executable (`target/release/reference`, built by `cargo test --release -p testing --features target-<name>`). Set `DIFFERENTIAL_LOG_EXCEPTIONS` to log (on the reference process's stderr) every applied exception and `TPM_RC_RETRY` re-issue. For fuzzing, `Tpm::with_seed(seed)` fixes the seed, `Tpm::reset()` returns a `Tpm` to the state of a new one with the same seed (the simulator is reset in place by `Simulator::reset_reference`; the reference processes are re-initialized by `Request::Reinit`/`Server::reinit`, no process is launched), and `Tpm::try_exchange(locality, command)` returns a divergence as `SendError::Divergence { response, divergences: Vec<Divergence> }` (each with the reference's response) instead of panicking; with `TPM_FUZZ_RECORD_DIR` set, every `Tpm` records its commands and responses (`testing::tpm::trace`, format v1). With the opt-in `fuzz-inproc` feature of `testing` (together with a target), `testing::differential::inproc::InProcReferences` hosts the target's C reference in the calling process (a `server::Server` over a `CReference`, with the interface of `References`: `launch`, `reinit`, `advance_clock`, `signal`, `hash_*`, `exchange`/`try_exchange`), and `Tpm::with_seed_in_process(seed)` builds a `Tpm` mirrored to them instead of to reference processes. The C references keep their state in globals, so at most one `InProcReferences` exists per process at a time (a second one panics); in-process mirroring is for single-threaded users such as the fuzz targets. `FUZZ_C_COVERAGE=1` compiles the C references with `-fsanitize=fuzzer-no-link` (with `clang`), so new C paths count as fuzzing coverage (the archives then link only into fuzz targets).

- **`testing/fuzz`** (crate `tpm2-fuzz`, its own workspace, excluded from the root workspace): differential `cargo fuzz` target `diff_conversation` (`fuzz_targets/diff_conversation.rs`). One input is a multi-round `model::Conversation` (at most 32 `Step`s: `Raw` bytes, a structured `Cmd { tag, code, handles: Vec<HandleOperand>, sessions: Vec<SessionSel>, params: Vec<Segment>, fixups }`, or an event: `Platform(PlatformOp)` (a `PLATFORM_SIGNALS` signal `PowerOff`/`PowerOn`/`NvOn`/`NvOff`/`Reset`, or `_TPM_Hash_Start`/`Data`/`End`), `Sleep(ms)` (virtual clock) or `Locality(n)` (locality of the following commands)) with a hand-written total decoder (`Conversation::from_bytes`, also its `Arbitrary`) and encoder (`to_bytes`; `from_bytes(to_bytes(c)) == c`). `HandleOperand::{Response,Nv,Session}{back}` and `Segment::{Value,Mutated}(ValueRef { kind: FieldKind, back })` refer to earlier responses by kind and recency; `Segment::Sized` and `Fixups` (commandSize/authSize/TPM2B sizes, each overridable) keep commands well formed. `pool::ValuePool` collects response handles, typed response fields (field-by-field `tpm2` `Unmarshal`, plus a full typed-response cross-check) and driver facts (NV indices, auth values, Names, flushed handles); `builder` resolves and assembles commands; `session::SessionEngine` builds and verifies auth areas (password, HMAC with rolling nonces and response-HMAC checks, policy, raw; deterministic `nonceCaller`; CFB/XOR parameter encryption; `corrupt_hmac` bit flips); `driver::Driver::round(&mut Tpm, &Step)` builds the command, sends it with `Tpm::try_exchange(locality, ..)`, checks the response (`wire::check_response`) and updates the pool and sessions, or applies an event step (power/reset signals also clear the session engine's sessions; commands while powered off and `_TPM_Hash_*` while powered off are skipped; hash data is cut at `MAX_HASH_DATA` = 4096). The fuzz crate compares with one target (its features `target-mstpm20` (default), `target-mstpm20-v185`, `target-ibmswtpm2`, forwarding to `testing`'s; fuzz each reference in its own campaign). One `Tpm::with_seed(driver::FIXED_SEED)` (`4242:1000000`; `Tpm::with_seed_in_process` with the fuzz crate's `inproc` feature, which enables `testing/fuzz-inproc`) is reused and `reset()` before each input. Findings panic with `DIVERGENCE[<impl>:round<i>:<cc>:<rs_rc>:<ref_rc>]`, `MALFORMED_RESPONSE[round<i>:<cc>]`, `UNPARSEABLE_RESPONSE[round<i>:<cc>]`, `BAD_RESPONSE_HMAC[...]`, `BAD_RESPONSE_AUTH[...]` or `ACCEPTED_CORRUPT_HMAC[...]`, unless globs in `testing/fuzz/known_divergences.txt` (or the file named by `TPM_FUZZ_KNOWN_DIVERGENCES`) suppress all of the finding's signatures; `TPM_FUZZ_STATS=<n>` prints counters every n inputs. The recommended build is in-process without sanitizer (`cargo fuzz build --fuzz-dir testing/fuzz -O -s none --features inproc diff_conversation`, run with `-detect_leaks=0`); process mode (without `inproc`) needs `REFERENCE_BIN` (the `reference` binary of the same target). Fuzz tools in `testing/fuzz/src/bin/` (shared code in `src/bin/shared/`, E2E trace fixtures in `src/bin/shared/testdata/`): `gen_dict` regenerates `testing/fuzz/tpm2.dict` (libFuzzer dictionary of the `tpm2` constants: TPM_CC/ALG/RH/RS_PW/ST/ECC/SU/SE/CAP and TPMA_OBJECT/NV/SESSION, big-endian); `trace2conv [--verify [--ecc-variants]] <out> <traces>` converts `TPM_FUZZ_RECORD_DIR` traces (recorded with `TPM_REFERENCE_SEED=4242:1000000`) into `diff_conversation` inputs (signals, `_TPM_Hash_*`, clock advances and locality changes become event steps), turning handles and fields of earlier responses into `HandleOperand::Response`/`Nv` and `Segment::Value` references (`--ecc-variants` adds cheaper variants with RSA key templates rewritten to ECC P-256, or capped at 2048 bits, checked by replay); `to_test [--name] <crash>` replays an input and prints a ready-to-paste E2E test (resolved bytes via `tpm.send_command(0, …)` on `Tpm::with_seed(FIXED_SEED)`). The minimized seed corpus is generated locally into `testing/fuzz/corpus/diff_conversation/` (gitignored, not committed: record E2E/Go traces with `TPM_FUZZ_RECORD_DIR`, convert them with `trace2conv --verify --ecc-variants`, add the session seeds, and minimize with `-merge=1`/cmin); build, run, triage and corpus-regeneration steps are in `testing/fuzz/README.md`.

### Reference RNG (`reference-rng`)
`tpm2-impl`, `tpm2-platform-linux` and `tpm2-simulator` have an opt-in `reference-rng` feature (described in `differential.md`, "Methodology", section "M.4 Determinism: Randomness and Time") that makes `tpm-rs` reproduce the random-number generation of the C references exactly instead of patching the references. `tpm2-impl/src/reference_rng/` links the original `mstpm20` C code instead of porting it: with the feature, `tpm2-impl/build.rs` clones `mstpm20` at the commit pinned by `testing/build.rs` (checked), applies `testing/patches/mstpm20/*.patch` (sorted), compiles only unmodified reference files (`CryptRand.c`, `CryptPrime.c`, `CryptPrimeSieve.c`, `CryptRsa.c`, `CryptEcc*.c`, `CryptHash.c`, TpmBigNum on OpenSSL, ...; there is no hand-written C), with command-line macros redirecting the reference's mutable globals to Rust accessors (`-Dgo=(*tpmrs_refrng_go())`, likewise `g_cryptoSelfTestState`, `primeLimit`), `CryptRsa.c` with `-fkeep-static-functions` and its `static` encoders globalized by `objcopy`, partially links them with `libcrypto.a` (`ld -r --gc-sections`), prefixes the entry points Rust calls and the platform functions the C calls (`_plat__GetEntropy`, `_plat__InFailureMode`, `_plat__IsCanceled`, `EnterFailureMode`, implemented in Rust, and `CryptTestAlgorithm`, a never-reached stub: the linked code's `g_toTest` stays zero because `tpm-rs` runs the self tests itself) with `tpmrs_refrng_` (`objcopy --redefine-sym`), localizes every other symbol and links the result as `libtpmrs_refrng.a` (plus `-lz -lzstd`); `bindgen` (build-dependency) generates the Rust types and prototypes from the reference headers into `OUT_DIR`. All glue is Rust in `reference_rng/ffi.rs`: `DrbgState` ↔ `DRBG_STATE` and slice ↔ `TPM2B` conversions, the per-call state (the TPM's DRBG as `go.drbgState`, self-test flags, prime limit, failure flag, entropy source) on the caller's stack published through a POSIX `pthread_key_t` (libc crate; no `std`/`alloc`), a reentrancy guard, failure mode → `TPM_RC_FAILURE`; without the feature no C is built. The safe Rust API is `RefRng` (the TPM's DRBG + entropy source) with `drbg` (`CryptRand.c`: instantiate/startup/reseed/stir/generate/`DRBG_InstantiateSeeded`/`DRBG_AdditionalData`), `rsa` (`CryptRsaGenerateKey()`, `OaepEncode()`/`RSAES_PKCS1v1_5Encode()`/`PssEncode()`) and `ecc` (`CryptEccGenerateKey()`, `CryptEccNewKeyPair()`, the FIPS pairwise test, ECDSA); all `unsafe` is in `reference_rng/ffi.rs`; `vectors.rs` checks against C outputs. With the feature, every random value of the engine is drawn through `TpmEngine::random_platform`/`random_crypto` (`src/rng.rs`) from the DRBG (`GlobalState::drbg_state`, persisted and reloaded like the reference's `go.drbgState`), in the reference's order, and object creation, ECDSA/PSS signing, RSA encryption and ephemeral ECC keys use `handler/reference_ops.rs` (the counterpart of `CryptCreateObject()` etc., on the linked C code); without it, the platform RNG and the crypto provider's CSPRNG are used as before. `tpm2-platform-linux` adds `GlibcRand` (glibc `rand()`), `ReferenceEntropy` (the references' `_plat__GetEntropy()`: `rand()` seeded with `realtime ^ pid` on `Rng::init`), `VirtualClock`, `LinuxRng::reference` and `LinuxTimer::new_virtual`/`advance`; `tpm2-simulator` adds `Simulator::advance_clock` and `create_reference_simulator!(pid, realtime_ms)`. `testing::tpm::Tpm` is always such a simulator, built from the seed it chooses (`ReferenceSeed::choose`: the test process's pid and monotonic ms, or `TPM_REFERENCE_SEED`) and hands to its references, so runs differ unless `TPM_REFERENCE_SEED` is set; client-side randomness comes from the OS unless it is set. `_common::sleep` (= `tpm::sleep`) advances the virtual clocks of the thread's TPMs (no wall-clock time passes); tests must sleep with it (never `std::thread::sleep`). `testing` supports only the `bssl` backend.

To ensure code quality and consistency, all changes must pass the following verification steps:
```bash
# Check that the project compiles without producing binaries
cargo check

# Enforce standard code formatting
cargo fmt --check

# Run the linter (including test targets) and deny all warnings
cargo clippy --all-targets -- -D warnings

# The full test suite (every test with --release): workspace, reference-rng, crypto backends,

make test
# Formatting, clippy (also of every differential target, reference-rng and without SHA-512) and docs
make lint

# Individual parts of `make test`:
# Execute all unit and integration tests
cargo test --release

# Execute tpm2-impl tests with the reference RNG port
cargo test --release -p tpm2-impl --features reference-rng

# Execute the E2E tests differentially against one C reference TPM (target), with tpm-rs built
# with that reference's profile; `make test-differential` runs all three
cargo test --release -p testing --features target-mstpm20
cargo test --release -p testing --features target-mstpm20-v185   # needs TPM-Internal access
cargo test --release -p testing --features target-ibmswtpm2

(cd testing/fuzz && cargo test --release --lib && cargo test --release --bin gen_dict --bin trace2conv --bin to_test)
```

## Coding Style
We follow strict coding standards to maintain safety and readability:
- **Idiomatic Rust & Design**: Use idiomatic Rust with proper software engineering design.
- **No Unsafe Code**: All crates must forbid unsafe code by including `#![forbid(unsafe_code)]` at the crate root (except `tpm2-crypto-bssl`, which uses `#![deny(unsafe_code)]` at the crate root and `#![forbid(unsafe_code)]` on all modules except `src/bssl.rs`, where safe FFI wrappers over `bssl-sys` are encapsulated; `tpm2-impl` with its opt-in `reference-rng` feature, which then uses `#![deny(unsafe_code)]` instead of `#![forbid(unsafe_code)]` (`cfg_attr`) and confines all `unsafe` to `src/reference_rng/ffi.rs`, the safe wrappers over the linked C reference RNG; and `testing` in a differential build (a `target-*` feature), which then uses `#![deny(unsafe_code)]` instead of `#![forbid(unsafe_code)]` (`cfg_attr`) and confines all `unsafe` to `src/differential/inproc.rs`, the safe wrappers over the linked C reference TPMs).
- **Rich Comments**: Use rich, explanatory comments (especially doc comments for public APIs) to describe the purpose, behavior, and any edge cases of functions, structs, and modules.
- **Rich Unit Tests**: Ensure high code coverage with extensive unit tests. Edge cases and error conditions should be explicitly tested.
- **No `alloc` and `libc` Dependencies in Core Crates**: The core crates (`tpm2` and `tpm2-impl`) are `#[no_std]` and must not depend on `alloc` or `libc`. Using `alloc`, `libc`, and other standard library components is permitted in tests and other crates. Exception: `tpm2-impl`'s opt-in `reference-rng` feature links C code (the reference RNG library, which uses libc and OpenSSL) and uses the `libc` crate for POSIX thread-local storage; the Rust code stays `no_std` without `alloc`.
- **Coding Guidelines**: Follow the [Google Rust Style Guide](https://google.github.io/styleguide/rustguide.html).
